## What it is

A no-gimmick web app that ranks **legal Washington-state cannabis deals by _true cost_** — sticker price **+** the cost of gas to drive there. The product's core insight: the cheapest sticker price is often **not** the cheapest way to actually obtain the product once driving is included.

- **Live:** https://gmaslist.com (Render free plan, single Node web service)
- **Design north star:** a precise utility tool (finance/transit-app energy), dark, calm, no leafy/neon "420" tropes.
- **Regulated content:** mandatory 21+ age gate and verbatim WAC 314-55-155 warnings (see `GMAS_LIST_BRIEF.md` §7, `client/src/constants/legal.ts`).

## Executive summary

The app is a **multi-part monorepo**. A React client renders a true-cost-ranked deal feed. An Express server serves both the built client and a tiny public read API (`GET /api/data`) backed by a flat `data.json` file. Deal data is refreshed **out of band** by an hourly GitHub Actions cron that runs the Node scrape pipeline (booting a Python Playwright stealth scraper in-job for Dutchie menus) and pushes results via authenticated `POST /api/ingest`. On Render the service is **read-only** over `data.json` — the cron is the sole writer (ADR-034).

The true-cost formula is the product:

```
trueCost = salePrice + driveCost
driveCost = roundTripMiles * (gasPrice / mpg)   // gasPrice from EIA (WA weekly regular); mpg user-selectable
```

## Architecture type

- **Repository:** multi-part monorepo (per-part `npm install --prefix`, not workspaces).
- **Runtime topology:** single Render Node web service serving React build + Express API from one origin. Data refresh is external (GitHub Actions). The Python scraper is **not** a deployed service — it is booted inside the Actions job.
- **Data store:** flat-file `server/data/data.json`, written atomically under an in-process lock. Render's filesystem is ephemeral, so it resets to the committed seed on redeploy and is re-hydrated by the next hourly cron POST.
