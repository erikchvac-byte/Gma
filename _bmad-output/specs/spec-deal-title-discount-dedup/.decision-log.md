# Decision log — spec-deal-title-discount-dedup

## 2026-06-22 — Create

**Input:** Interactive bug report via /bmad-spec — duplicate discount label on the deal card; the styled "50% off" badge is correct, but the title (`deal.description`, e.g. "50% off Select Brands") is also prefixed with the discount phrase, reading "50% off · 50% off Select Brands". Strip the prefix from the title string only; leave badge and stored description untouched.

**Grounding:** Read `client/src/components/DealCard.tsx` and `client/src/utils/dealView.ts`. Confirmed the badge = `gma-deal-block__pct` (`{discountPct}%`) + `gma-deal-block__off` ("off"), and the title = `deal.description` rendered verbatim by `dealTitle()`. There is no code-side prepend of "50% off · " — the redundancy is the scraped description embedding the magnitude the badge already shows; the "·" the reporter sees is visual separation between badge and title. So the fix lives in the `dealTitle` display derivation.

**Mode:** Express distill — input was rich and code-grounded, no elicitation needed. One capability (CAP-1).

**Self-validate.**
- *Pass 1 (coherence, rules 1–6, 8):* CAP-1 carries both intent and success; intent is WHAT (suppress redundant prefix) not HOW; constraints each rule something out (display-only, badge untouched, match-only-discount-prefix, empty-fallback); one+ non-goals present; success signal is demonstrable ("magnitude appears exactly once"). Lean prose. PASS.
- *Pass 2 (preservation):* Every load-bearing source claim landed — badge stays (Constraint 2 / Non-goal 1), original `deal.description` value unchanged (Constraint 1 / Non-goal 2), strip title-string-only (CAP-1 + Constraint 1). Two unresolved points became Assumptions + an Open Question (match the badge's exact `discountPct` vs any "N% off" token; empty-result fallback resolved in Constraint 4). No wrapper-only content dropped.

**Verdict:** Coherent and fully preserving. One open question on match strictness; the stricter value-matched reading is assumed so downstream can proceed without blocking.

## 2026-06-22 — Update (scope decision)

Erik clarified the fix is not hardcoded to "50" — it must cover **any** percentage. Discussed whether to also strip non-percent forms ("$5 off", "BOGO"). Surfaced that the badge is **percent-only**, so for non-percent deals there is no badge to duplicate and stripping would erase the card's sole discount text.

**Decision (Erik):** go with the **badge-anchored** approach — strip a leading "N% off" phrase for any N, but only when the percent badge is actually rendering that magnitude. Defer non-percent prefixes to a separate work session.

SPEC updated accordingly: CAP-1 generalized to any N (multi-value test); new badge-anchored Constraint; non-percent forms moved to Non-goals as explicitly deferred; prior Open Question resolved and removed; Assumptions collapsed to the resolved decision. No implementation performed.

## 2026-06-22 — Update (case-insensitivity + dangling-word edge case)

Erik surfaced a concrete live-data example: `deal.description = "15% Off Edibles + Drinks (Excluding Capsules)"` — capital "Off". Two risks this exposes:

1. **Case mismatch.** The badge renders lowercase "off" and the SPEC's only example used lowercase "50% off", but real scraped copy uses capital "Off"/"OFF". A case-sensitive match against "off" would silently no-op on most live data — the stutter would persist in production while the unit test (lowercase) passed.
2. **Dangling word.** Stripping only "15% " (number+percent+space) would leave the title reading "Off Edibles + Drinks …" — a broken fragment, worse than the original stutter. The word "off" and its trailing whitespace must be consumed as part of the one phrase.

**Decision (Erik):** fix both. Match is case-insensitive; the strip consumes the whole leading phrase as a unit (number + "%" + "off" + trailing whitespace/separator), trimmed defensively, so the result is "Edibles + Drinks (Excluding Capsules)" with no orphan "Off" and no leading space.

SPEC updated: CAP-1 success criteria now asserts the capital-"Off" example, the no-dangling-word and no-leading-space outcomes, and a multi-casing unit test ("off"/"Off"/"OFF"); new Constraint mandates case-insensitive whole-phrase consumption with the no-op-on-live-data rationale. No implementation performed.
