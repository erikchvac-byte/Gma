## What Went Well

- **Cross-story blocker discipline.** Story 4.1 closed the single-writer race the Story 3.1 review flagged (`withDataLock` promise-chain mutex), keeping `refreshGasPrice` and `runScrapers` from clobbering `data.json`. The 3.1→4.1 handoff via `deferred-work.md` worked as intended; 45/45 tests on first run.
- **Graceful degradation as a design spine.** Every layer returns `[]`→stale rather than throwing: the scraper contract, the orchestrator's defense-in-depth try/catch, `scraperClient` on a dead service, and the 4.3 deferred-id guard. A broken source can never poison the feed or crash the server.
- **Tier-agnostic architecture held.** The two-tier plan (ADR-016 Axios+Cheerio / ADR-017 Python microservice) kept `runScrapers` ignorant of which tier a scraper uses — 4.3 added the Dutchie path with zero engine changes.
- **Stopped and re-scoped instead of plowing ahead.** Story 4.2 paused after live investigation rather than forcing parsers onto sites that couldn't be scraped that way.

## What Was Hard / Key Lessons

1. **Planning assumptions didn't survive contact with the live sources.** Planning assumed ~4 plain-HTML scrapers; live HTML inspection in 4.2 found only `remedy-tulalip` is plain HTML — the other three are Dutchie. This paused 4.2 mid-flight for a re-scope decision and expanded 4.3 from one store to three. The architecture also documented the wrong example stores (Happy Time Mt Vernon/Pullman/Yakima, not the seeded Everett stores). **Lesson:** verify external-source assumptions against the live source before committing parser work.
2. **Silent-failure contracts are a latent-bug class.** `daysValid` must be full lowercase day names or `everyday`, and times must be 24-hour strings, or `filterActiveDeals` drops the deal with no error. Story 4.1's own fixtures used 3-letter abbreviations and got away with it because they never exercised the real consumer. **Lesson:** test scraper output against the actual consumer (`filterActiveDeals`), not just shape, so vocabulary mismatches fail loudly.
3. **"Code-complete" ≠ "data-complete."** Epic 4's goal was "deals come from real dispensary websites; app ready for R&D validation." The code is done and tested, but only 1 of 4 sources produces live deals today — the three Dutchie stores are stale until the deferred live pass, and there's still no real `EIA_API_KEY` in `.env`.

## Carried Debt / Honest Gap

- **Data-hardening was deferred to "Epic 4" by earlier reviews and not done.** Stories 2.5/2.6 (and 2.3) explicitly punted dispensary-payload validation at the `useDeals` boundary (a `null`/`NaN` `distanceMiles` or a null array element can crash a `DealCard`) and zero-length-window normalization at ingestion into "Epic 4 scraper-data hardening." Epic 4 wired the scrapers but did not pick this up — which matters now that real, less-predictable scraped data flows in. **Decision (Erik, 2026-06-13): promote to a tracked follow-up story.**

## Action Items

1. **Create a data-hardening follow-up story.** Scope: validate/normalize dispensary shape once at the `useDeals` boundary (drop/repair `distanceMiles` `null`/`NaN`/`Infinity` and non-object array elements before they reach `DealCard`/distance filter), and normalize or reject zero-length / degenerate time windows at scraper ingestion. **Owner:** Erik (kick off via `bmad-quick-dev` or `create-story`). **Success:** a malformed scraped dispensary can never crash a card; covered by tests.
2. **Run the 4.3 live pass (immediate next focus).** Per `deferred-work.md`: start the Python service on :8000; resolve embed store ids for `jet-cannabis-everett` and `kush21-everett-evergreen` (`/discover` or host lookup); reconcile `dutchie-specials.json` against a real `GetSpecialMenuCards` capture (watch the discount unit — fraction vs whole percent — and the time-window field path); add a real `EIA_API_KEY` to `.env`. **Owner:** Erik. **Success:** all four sources show live deals via `GET /api/data`; Epic 4 reaches data-complete.
3. **Bank the two process lessons.** (a) Verify live-source classification before parser work. (b) Exercise scraped output against `filterActiveDeals`, not just shape, in tests. **Owner:** carry into the hardening story and any future scraper work.
